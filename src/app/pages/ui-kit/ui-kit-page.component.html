Enlaces

appLink es una directiva (no un componente) que se aplica a un <a> real para enlaces de texto dentro de un párrafo. No tiene propiedades — solo agrega la clase de estilo del enlace. Para una acción que no sea navegación real, usa app-button con variant="link", ya que renderiza un <button> y así la tecnología de asistencia lo anuncia correctamente.

Encabezados

app-heading renderiza un h1–h4 semántico definido por level, con un estilo visual propio por nivel. appearance permite desacoplar el estilo del nivel semántico (p. ej. un h2 con apariencia de h1) para mantener una jerarquía de documento correcta sin sacrificar el diseño.

Propiedad Tipo Valor por defecto Descripción
level 'h1' | 'h2' | 'h3' | 'h4' requerido Tag HTML semántico a renderizar.
text string requerido Texto del encabezado.
appearance 'h1' | 'h2' | 'h3' | 'h4' igual a level Estilo visual a aplicar, independiente del tag semántico.

Tarjetas

app-card es un contenedor de contenido con tres slots proyectados: un elemento marcado con card-header, el contenido por defecto (sin marcar) como cuerpo, y un elemento marcado con card-footer. Ambos slots son opcionales. app-card-stat es un bloque pequeño de KPI pensado para colocarse dentro del slot card-header.

Tarjetas semánticas

app-semantic-card combina un ícono con color según la variante junto con un título y un texto, para mensajes destacados (aprobaciones, advertencias, anuncios). Cada variante tiene un ícono por defecto, que la propiedad icon puede sobrescribir.

Propiedad Tipo Valor por defecto Descripción

text string '' Texto de apoyo.
icon IconName | null null Sobrescribe el ícono por defecto de la variante (ver icon-registry.ts para los nombres disponibles).

Campos de entrada

app-text-input, app-select-input y app-textarea son campos de formulario con etiqueta que comparten el mismo patrón de error/ayuda: define error para mostrar un mensaje de validación (esto también toma el control de aria-describedby), o hint para un texto de ayuda cuando no hay error. Los tres emiten valueChange en cada entrada del usuario en lugar de usar binding bidireccional.

Casillas de verificación

app-checkbox admite binding bidireccional mediante [(checked)] y también implementa ControlValueAccessor, por lo que funciona con Reactive Forms (formControlName) sin necesidad de la sintaxis banana-in-a-box.

Propiedad Tipo Valor por defecto Descripción
checked (model) boolean false Estado marcado/desmarcado con binding bidireccional; también se puede definir desde un control de Reactive Forms.
disabled boolean false Deshabilita la casilla.
label string '' Texto que se muestra junto a la casilla.

Radios

Las opciones app-radio deben anidarse dentro de un contenedor con la directiva appRadioGroup, que administra el name compartido y el value seleccionado actualmente (con binding bidireccional y compatible con Reactive Forms). Cada app-radio lee su estado marcado desde el grupo.

Propiedad Tipo Valor por defecto Descripción
appRadioGroup (host directive)
name string autogenerado name compartido para los inputs de radio nativos dentro del grupo.
value (model) string | null null Valor de la opción seleccionada actualmente; con binding bidireccional y compatible con Reactive Forms.
app-radio
value string requerido Valor que representa esta opción dentro del grupo.
disabled boolean false Deshabilita esta opción (independiente del estado deshabilitado del grupo).
label string '' Texto que se muestra junto al radio.
